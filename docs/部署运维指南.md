# 🚢 部署与运维指南

> 版本：v3.3.1 · 更新日期：2026-08-17

## 1. 环境要求

| 组件 | 最低要求 | 建议 |
|------|----------|------|
| Python | 3.10 | 3.10.11（已验证） |
| Node.js | 18 | 20+ |
| 内存 | 2GB | 4GB+（含嵌入模型） |
| 磁盘 | 1GB | 5GB+（含模型缓存、日志） |
| GPU | 可选 | 有 CUDA 可显著加速向量化 |
| 网络 | 可访问千问 API | 模型下载走 hf-mirror 镜像 |

## 2. 本地部署（开发机 / 个人电脑）

```bash
# 1. 克隆/解压项目
cd drink_rag_robot

# 2. 创建虚拟环境（推荐）
python -m venv .venv
.venv\Scripts\activate            # Windows
source .venv/bin/activate          # Linux/macOS

# 3. 安装后端依赖
pip install -r backend/requirements.txt

# 4. 安装前端依赖并构建
cd frontend && npm install && npm run build && cd ..

# 5. 配置密钥
cp .env.example .env
#    编辑 .env，填写 LLM_API_KEY

# 6. 一键启动
python start.py
#   访问 http://127.0.0.1:8000
```

## 3. 服务器部署（Linux）

### 3.1 方案 A：systemd 托管（推荐）

创建 `/etc/systemd/system/drink-rag.service`：

```ini
[Unit]
Description=Drink RAG Robot
After=network.target

[Service]
User=www-data
WorkingDirectory=/opt/drink_rag_robot
EnvironmentFile=/opt/drink_rag_robot/.env
ExecStart=/opt/drink_rag_robot/.venv/bin/uvicorn backend.main:app --host 0.0.0.0 --port 8000 --workers 1
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now drink-rag
```

> 说明：嵌入模型与向量索引在进程内共享，**必须 `--workers 1`**，多 worker 会重复加载模型并互相覆盖内存索引。

### 3.2 方案 B：Docker

```dockerfile
# Dockerfile（后端+前端一体化镜像）
FROM python:3.11-slim
WORKDIR /app
COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
WORKDIR /app/frontend
RUN npm install && npm run build
WORKDIR /app
EXPOSE 8000
CMD ["uvicorn", "backend.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

```bash
docker build -t drink-rag:3.0 .
docker run -d --name drink-rag \
  -p 8000:8000 \
  -v /opt/drink-rag-data:/app/data \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  --env-file .env \
  drink-rag:3.0
```

### 3.3 方案 C：Nginx 反向代理（生产）

```nginx
server {
    listen 80;
    server_name drink-rag.example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # SSE 流式必需：关闭缓冲
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 180s;
    }
}
```

## 4. 环境变量速查（.env）

| 变量 | 默认 | 说明 |
|------|------|------|
| `LLM_API_KEY` | - | 千问 DashScope 密钥（必填） |
| `LLM_MODEL` | qwen-plus | qwen-turbo / qwen-plus / qwen-max |
| `HOST` / `PORT` | 0.0.0.0 / 8000 | 监听地址 |
| `DEBUG` | false | 调试模式 |
| `RAG_USE_RERANKER` | false | 是否启用交叉编码器重排（需模型） |
| `RAG_TOP_K` | 4 | 最终送入 LLM 的条数 |
| `RAG_CHUNK_SIZE` | 500 | 分块大小 |
| `ENABLE_QUERY_REWRITE` | true | 多轮查询改写 |
| `CORS_ORIGINS` | * | 跨域白名单（逗号分隔） |

## 5. 日志与数据

| 内容 | 路径 |
|------|------|
| 应用日志 | `logs/app.log`（滚动 5MB×5） |
| SQLite 数据库 | `data/drink_rag.db` |
| 上传文件 | `data/uploads/` |
| 模型缓存 | `~/.cache/huggingface/` |

**备份策略**：定期备份 `data/drink_rag.db` 与 `data/uploads/`；重启即从 DB 重建索引，无需备份向量文件。

## 7. 故障排查

| 症状 | 排查方向 |
|------|----------|
| 前端白屏 | 检查 `frontend/dist` 是否构建；看浏览器控制台 API 是否 404 |
| 模型下载失败 | 检查 `HF_ENDPOINT`；镜像不可达时换官方源 |
| 重排启用后很慢 | 模型未下载会阻塞；改为 `RAG_USE_RERANKER=false` 或等待下载完成 |
| 回答无依据/幻觉 | 检查检索命中：`/api/knowledge/search` 调试 query；调低 `RAG_SIMILARITY_THRESHOLD` |
| 上传 PDF 无内容 | 扫描件/图片型 PDF 无法提取文本，需转文本 |
| `torch.load` 报安全错误 | 模型非 safetensors 导致；本项目已强制 `use_safetensors=True` |

## 8. 性能调优建议

| 场景 | 建议 |
|------|------|
| 首响应延迟高 | 关闭查询改写 `ENABLE_QUERY_REWRITE=false` |
| 答案太长/超时 | 调低 `LLM_MAX_TOKENS` |
| 检索不准 | 调大 `RAG_RETRIEVE_K`、开启重排 |
| 召回过多噪音 | 调高 `RAG_SIMILARITY_THRESHOLD` |
| GPU 显存小 | 嵌入/重排模型可强制 `RAG_EMBED_DEVICE=cpu` |
