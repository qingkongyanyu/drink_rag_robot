## 2. 设计原则

1. **分层清晰**：`api（路由）→ services（业务）→ rag（算法）→ core（基础设施）`，
   单向依赖，便于测试与替换。
2. **工厂 + 单例**：RAG 引擎、嵌入模型、配置均单例化，进程内只初始化一次，避免重复加载。
3. **惰性加载**：嵌入/重排模型首次使用时才加载，启动速度快、失败可降级。
4. **配置外置**：所有可调参数集中在 `backend/core/config.py`，通过 `.env` / 环境变量注入，
   密钥绝不硬编码进源码。
5. **健壮降级**：重排模型缺失 → 跳过重排；查询改写失败 → 使用原始问题；RAG 检索失败 → 直答提示。
6. **流式优先**：对话默认走 SSE 流式，提升体验；同时保留非流式接口。

## 4. 核心数据流

### 4.1 一次问答请求（流式）

```
用户提问
  │
  ├─► 载入多轮历史（SQLite → 会话缓冲）
  ├─► 查询改写（LLM 指代消解，失败降级原问题）
  ├─► 混合检索（RAG 引擎）
  │     ├─► Dense：bge 向量 → FAISS cosine top-k
  │     ├─► Sparse：jieba + BM25 top-k
  │     ├─► RRF 融合 → 候选集
  │     └─► （可选）交叉编码器重排 → top-N
  ├─► 组装 Prompt（系统提示 + 历史 + 编号知识 + 问题）
  ├─► SSE 流式返回（meta → delta* → done）
  └─► 结果落库（对话 + 引用） + 当日统计
```

### 4.2 知识上传流程

```
上传文件 → 格式校验（扩展名/大小）
       → 文档解析（txt/md/csv/json/pdf/docx → 段落）
       → 智能分块（按句子边界 + overlap）
       → 建文档记录（processing 状态）
       → 批量语义嵌入 → 写入 FAISS
       → 回填 vector_id + 重建 BM25
       → 文档状态置 ready，可被检索
```

### 4.3 启动流程

```
uvicorn backend.main:app
  ├─► lifespan：初始化 SQLite（建表）
  ├─► 后台线程：构建 RAG 引擎（从 DB 重建向量 + BM25）
  ├─► 注入内置 100 款饮料知识库（幂等）
  └─► 服务就绪，前端访问 http://127.0.0.1:8000
```

## 5. 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| Web 框架 | FastAPI | 异步、Pydantic 校验、原生 OpenAPI 文档、SSE 支持好 |
| 嵌入模型 | bge-small-zh (512维) | 中文效果好、体量小、支持指令前缀优化检索 |
| 向量库 | FAISS IndexFlatIP | 精确检索无量化损失；语料规模下性能足够 |
| 稀疏检索 | 自研 BM25 | 零依赖、可解释、面试中体现算法功底 |
| 融合 | RRF | 对分数尺度不敏感、鲁棒，优于简单加权 |
| 重排 | bge-reranker-base | 交叉编码器精度最高，按需启用、可降级 |
| LLM 协议 | OpenAI 兼容接口 | 生态通用，可无缝切换任何兼容模型服务商 |
| 流式 | SSE | 原生支持、实现简单、兼容 Nginx 缓冲关闭 |
| 存储 | SQLite WAL | 零运维、单文件、适合中小规模项目 |
| 前端 | Vue3 + Vite | 组件化、生态成熟、构建产物由后端托管 |

## 6. 安全设计

- **密钥隔离**：API Key 只在 `.env`（已 gitignore），绝不入库；
- **路径安全**：上传文件名清洗 + 随机前缀，防路径穿越；
- **输入约束**：提问长度、上传大小、文件类型、并发均有限制；
- **渲染安全**：前端 Markdown 关闭 HTML 渲染，防 XSS；
- **CORS 可配置**：生产可收紧来源白名单。

## 7. 扩展性设计

- **新增知识源**：实现 `document_loader` 解析器 + 复用入库管道即可；
- **切换向量库**：`vector_store` 抽象了 add/search/soft_delete，可替换 Milvus/PGVector；
- **多模型接入**：`llm_service` 已按 OpenAI 协议抽象，一行配置切换；
- **分布式演进**：SQLite → PostgreSQL、本地 FAISS → 分布式向量库、模型服务化。

## 8. 目录依赖关系（自底向上）

```
backend/core        （无依赖）
backend/models      （依赖 pydantic，被 services/api 引用）
backend/rag         （依赖 core；embeddings 可独立）
backend/services    （依赖 core + models + rag）
backend/api         （依赖 services + models）
backend/main        （聚合以上所有）
```
