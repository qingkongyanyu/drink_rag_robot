## 2. 后端技术

### 2.1 Web 框架：FastAPI + Uvicorn

- **选型**：FastAPI（异步、原生 Pydantic 校验、自动生成 OpenAPI/Swagger 文档）。
- **为什么**：对话与知识库接口高频、SSE 流式输出需要长连接，FastAPI 的异步模型天然适配；
  `/api/docs` 交互式文档零成本交付，面试可直接演示。
- **SSE**：后端用 `StreamingResponse` 输出 `text/event-stream`，事件在 `data.type` 与 `event:` 行**双写**，
  前端两种解析方式都兼容（见 `api/chat.py`）。
- **备选**：Flask（旧版 v2 即 Flask，异步与文档能力弱，v3 重构时替换）；Django（过重，与项目规模不匹配）。

### 2.2 配置中心：pydantic v2 + 极简 .env 加载器

- `backend/core/config.py` 用 `pydantic.BaseModel` 定义全部可调参数，字段名对应 `.env` 环境变量；
- 手写约 20 行 `load_dotenv`（避免引入 `python-dotenv` 依赖），并把系统环境变量显式注入模型；
- 全部密钥外置 `.env`（已 gitignore），**绝不硬编码进源码**。

### 2.3 大模型：openai 官方 SDK + DashScope 兼容协议

- 统一走 `https://dashscope.aliyuncs.com/compatible-mode/v1`（千问的 OpenAI 兼容端点），
  用 `openai.OpenAI(base_url=...)` 调用；
- **SDK 内置**流式解析、超时、自动重试、异常分类，不再手写 HTTP/SSE；
- 业务层保留两件事：① 错误 → HTTP 状态码映射（401/408/429/502/503，见 `services/llm_service.py`）；
  ② 多轮**查询改写**（指代消解）；
- **可切换**：改 `LLM_BASE_URL` 一个参数即可接任意 OpenAI 兼容服务商（OpenAI / Ollama / 火山方舟等）。
- **备选**：`langchain_openai.ChatOpenAI`（本项目检索链路全自研，引入 LangChain 只会带来版本断裂与黑盒）；
  直接手写 `requests`（早期版本，SSE 解析脆弱，已替换）。

### 2.4 嵌入模型：sentence-transformers + bge-small-zh

- `BAAI/bge-small-zh`：中文检索专用双塔模型，**512 维**，约 100MB，CPU 可跑、GPU 更快；
- 查询侧加 BGE 官方指令前缀（`为这个句子生成表示以用于检索相关文章：`），文档侧不加——官方推荐做法；
- 工程细节：批量编码（batch=32）、查询向量 **LRU 缓存**、惰性加载（首次检索才加载，启动秒级）；
- 模型下载走国内镜像 `hf-mirror.com`（`HF_ENDPOINT` 可覆盖）。

### 2.5 向量检索：FAISS（IndexFlatIP）

- 向量 L2 归一化后，**内积 = 余弦相似度**，用 `IndexFlatIP` 精确索引一次搞定；
- 精确检索无量化损失，当前规模（数百块）下单次检索 < 10ms，无需 HNSW 等近似索引；
- 软删除 + 垃圾阈值自动重建，解决 FAISS 不支持删除的问题。
- **备选**：Milvus / PGVector（分布式、更大规模时替换，`vector_store` 已抽象 add/search/delete 接口）。

### 2.6 稀疏检索：自研 BM25（jieba + numpy）

- 分词用 `jieba`（精确模式），打分用经典 BM25 公式（`k1=1.5, b=0.75`）；
- tf / doc_len / doc_freq 全部用 **numpy 矩阵运算向量化**，单次检索是矩阵乘法而非逐文档循环；
- **为什么自研**：零额外依赖、完全可控、可解释（面试可直接讲公式与推导）；
- 与稠密检索互补：BM25 对专名/编号精确，向量对语义近义强。

### 2.7 持久化：SQLite（WAL）

- 标准库 `sqlite3` + **WAL 模式**，每次操作独立连接（线程安全）；
- 4 张表：`conversations`（对话）、`knowledge_docs`（文档）、`knowledge_chunks`（分块）、`stats_daily`（统计）；
- **零运维**、单文件备份简单，适合中小规模；重启即从 DB 重建向量索引，无需备份向量文件。
- **备选**：PostgreSQL（并发与规模上来后平滑迁移，SQL 语句已按通用方言书写）。

### 2.8 文档解析：pypdf / python-docx

- `document_loader.py` 统一解析 `txt / md / csv / json / pdf / docx`，输出标准段落结构；
- 图片型 PDF（扫描件）无法提取文本——已知限制，文档中已注明。

## 3. 前端技术

### 3.1 Vue 3 + Vite

- **Composition API + `<script setup>`**，组件化清晰（`views/` 页面、`components/` 组件、`composables/` 逻辑复用）；
- Vite 开发服务器热更新 + 构建产物 `dist/` 由后端 FastAPI 直接托管（SPA 回退），单端口部署；
- 路由级代码分割，首屏 < 100KB gzip。

### 3.2 Pinia + Vue Router

- Pinia 三个 store：`chat`（会话/流式）、`knowledge`（文档）、`system`（监控状态）；
- Router 三个视图：`/chat`、`/knowledge`、`/dashboard`。

### 3.3 网络层：Axios + fetch(SSE)

- Axios 封装统一 `{code, msg, data}` 响应与错误拦截（`api/request.js`）；
- 流式走 **fetch + ReadableStream** 手写 SSE 解析（`api/chat.js`），兼容 `event:` 行与 `data.type` 双形态。

### 3.4 ECharts

- 系统监控页：近 14 天问答/上传趋势折线图、知识分类饼图、RAG 参数一览卡片。

### 3.5 Markdown-it（安全渲染）

- 回答以 Markdown 渲染，**关闭 HTML 渲染**防 XSS，代码块/表格样式增强（`utils/markdown.js`）。

### 3.6 设计系统

- CSS 变量令牌（`styles/base.css`）驱动 **深/浅双主题**、玻璃拟态卡片、极光动效背景、微信风聊天气泡（左 AI / 右用户）。

## 4. 一次问答背后的技术流

```
浏览器输入问题
  └─ Vue3 组件捕获 → Pinia chat store
       └─ fetch SSE POST /api/chat            （Axios 同源，FastAPI 托管）
            └─ FastAPI 路由（Pydantic 校验）
                 └─ chat_service 编排
                      ├─ SQLite 读历史
                      ├─ openai SDK → 查询改写         （LLM 1 次）
                      ├─ bge 嵌入 → FAISS 余弦召回      （Dense）
                      ├─ jieba+BM25 关键词召回          （Sparse）
                      ├─ RRF 融合 → （可选）重排
                      └─ openai SDK → 流式生成          （LLM 2 次，SSE）
                           └─ StreamingResponse 逐 token 推回前端
                                └─ Vue 打字机效果 + Markdown-it 渲染 + 来源折叠
```

## 6. 关键选型对比（面试高频）

| 场景 | 本方案 | 常见备选 | 取舍 |
|------|--------|----------|------|
| 检索框架 | 全自研 | LangChain / LlamaIndex | 可讲清每个细节、无版本断裂；牺牲生态便利 |
| 向量库 | FAISS | Milvus / PGVector / Weaviate | 零运维、够快；规模大了再换 |
| 融合 | RRF | 加权求和 | 对分数尺度不敏感、无需调权 |
| 嵌入模型 | bge-small-zh | text2vec / m3e / OpenAI ada | 中文效果好、体积小、本地运行免调用费 |
| LLM 调用 | openai SDK | langchain_openai / 手写 HTTP | SDK 内置重试流式；不用 LangChain 保可控 |
| 数据库 | SQLite | PostgreSQL / MySQL | 零运维；并发上来再迁移 |
| 前端 | Vue3 + Vite | React + Webpack | 上手快、构建快、与 FastAPI 同栈心智 |
