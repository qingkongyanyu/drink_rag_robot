# 🎯 面试要点速览（项目讲解指南）

> 面向面试官介绍本项目时的核心话术与技术亮点。基于真实代码，可逐条展开。

## 1. 一句话介绍

> 「这是一个**生产级细节**的 RAG 问答系统：把 100 款饮料的结构化知识 + 用户上传文档，通过
> **语义向量 + BM25 双路召回、RRF 融合、交叉编码器重排**检索出依据，再交给千问大模型生成
> 带**来源引用**的回答，前端流式呈现，并配套完整的知识库管理与系统监控。」

## 2. 技术栈一句话

> FastAPI（异步） + Vue3/Vite（前端） + sentence-transformers（嵌入） + FAISS（向量库）
> + 自研 BM25 + 千问大模型（OpenAI 兼容协议，SSE 流式） + SQLite（持久化）。

## 3. 面试高频问答

### Q1：为什么不用现成的 LangChain / LlamaIndex？

> 项目以**深入理解检索链路**为目标，核心检索组件均为自研：BM25 用 jieba + numpy 手写打分，
> 混合检索的 RRF 融合、向量库封装、分块策略都是自己实现的。这能让我对每一步的数学与工程细节
> 完全可控、可讲解、可调参，也避免了重量级框架的开销与黑盒。LangChain 的抽象在这里反而会
> 掩盖细节。

### Q2：混合检索是怎么做的？为什么 RRF 而不是加权求和？

> 双路召回：Dense 用 bge 中文向量在 FAISS 上做余弦检索（语义近义），Sparse 用 BM25 做字面
> 匹配（专名、编号更准）。融合时用 **RRF**：`score = Σ 1/(K + rank)`，只看排序位次。
> 因为两种检索器的分数尺度完全不同（余弦 0~1、BM25 无界），加权求和需要反复调权且不稳定，
> RRF 对尺度不敏感、无需调权、鲁棒。同时保留了加权融合作为可切换策略。

### Q3：为什么要重排？为什么不直接加大 top_k？

> 双塔（dense）对 query 与 doc 是独立编码，交互信息在后期才融合，排序可能不够精准。
> 交叉编码器把 (query, doc) 拼接后联合编码，全程交互，**精度显著更高**。但逐对打分慢，
> 所以只对融合后的 6 条候选重排取 4 条——**用可接受的小延迟换首条准确率**。
> 模型未就绪时自动降级，不影响主链路（健壮性设计）。

### Q4：如何控制幻觉？

> 三重手段：① 知识片段在 Prompt 中编号，强制 LLM 基于「参考知识库」作答，并明确要求
> "知识库不足时说明无相关记录"；② 要求回答标注 `[来源N]`，同时 API 返回 sources 元数据，
> 前端可溯源核对；③ 检索阈值过滤低相关片段，宁可"未检索到"也不硬编。

### Q5：多轮对话怎么处理？指代怎么消解？

> 两个层次：① 历史拼接进 Prompt 给 LLM 上下文；② 检索前用一次轻量 LLM 调用做**查询改写**
> （指代消解 + 意图补全），把"它呢？"改写成含实体的完整查询再去检索——否则 RAG 检索的是
> 残缺问题，必然召回失败。改写失败自动回退原问题。

### Q6：知识上传是怎么做到"秒级可检索"的？

> 上传 → 格式解析 → 智能分块（句子边界 + overlap）→ 批量 GPU 嵌入 → 写入 FAISS →
> 重建 BM25 → 事务性落库。全程增量：只处理新文档，不动已有索引；删除走软删除 + 阈值重建。

### Q7：性能如何优化？

> ① 模型惰性加载 + 后台预热，服务秒级可用；② 向量化 BM25 + FAISS 精确索引，单次检索
> <10ms；③ 嵌入 LRU 缓存 + 批量推理；④ 重排仅作用于小候选集；⑤ 前端路由级代码分割。

### Q8：为什么单 worker？能分布式吗？

> 索引与模型在进程内共享，多 worker 会重复加载模型并互相覆盖内存索引，所以部署强制
> `--workers 1`。扩展方向：把向量库外置为 Milvus/PGVector、模型服务化、DB 迁移 PostgreSQL
> —— 这些在代码里都做了抽象，替换成本低。

### Q9：如何评估检索质量？

> 提供 `/api/knowledge/search` 接口，任意 query 可查看命中内容 + score + 召回方式（dense/
> sparse/hybrid），前端"检索调试"页可视化；同时用答案引用率、人工抽检等方式评估。后续可加
> HitRate/MRR 等离线指标脚本。

### Q10：项目中你最有成就感/最难的实现？

> 可选：自研 BM25 的向量化（把 5 层循环压成一次 numpy 矩阵运算）；或软删除 + 阈值重建的
> 向量库（FAISS 不支持删除的工程解法）；或「查询改写 → 混合检索 → 重排 → 引用」整条链路
> 的鲁棒降级设计（每一环失败都有兜底）。

## 4. 展示节奏建议（5 分钟 Demo）

1. **开场**：打开主页，展示流式打字 + 来源引用折叠（30s）
2. **检索质量**：知识库页「检索调试」，输入"虚寒体质适合喝什么"，展示 hybrid 命中（1min）
3. **上传知识**：拖一个 md/txt，展示自动分块、秒级可检索（1min）
4. **多轮对话**：问可乐 → 追问"那无糖的呢？"，展示查询改写生效（1min）
5. **系统监控**：仪表盘展示引擎状态、向量指标、趋势图（30s）
6. **架构收尾**：讲混合检索 → RRF → 重排链路与降级设计（1min）

- 支持语音问答、多租户知识空间；
- 对接向量数据库与模型网关，走向生产级多实例。
